## 2024-05-30 - [Performance Issue in Transposition Table]
**Learning:** The `TranspositionTable` class in `src/main/kotlin/engine/ZobristHashing.kt` has a major performance bottleneck. Both `save` and `probe` methods (especially `probe`) are iterating through the entire table (`sizePowerOfTwo = 1 shl 20` or 1,048,576 elements) looking for a matching key or a replacement slot. This turns an O(1) hash table lookup into an O(N) linear search, which is devastating for a Minimax engine that calls these methods millions of times per second.

**Action:** Fix the hashing logic in `TranspositionTable`. The `probe` method should use the hash value to index into the table (`val index = (hash.toInt()) and mask`) instead of iterating through the entire table. The `save` method already calculates the index but doesn't use it, doing a linear scan instead (or rather, the code shows it just checking the passed entry which seems like it might be broken if `save` is supposed to insert - wait, `save` takes `entry: TransitionTableEntry`, so it's modifying the passed object, which means it relies on `probe` returning the correct entry reference to mutate).
